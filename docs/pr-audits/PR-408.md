# Audit Report — Upstream PR #408 (`torch` implementation of Time-to-event `CoxProportionalHazard` models)

- **Upstream URL**: https://github.com/slideflow/slideflow/pull/408
- **Upstream Branch**: `slideflow:cph` → `master` (15 commits, 13 files — conflicted against Slideflow 3.1.0)
- **Original Author**: `jamesdolezal` (with contributions on `cph` branch)
- **Fork Audit Branch**: `pr-audit/408-torch-cph`

## Audit Findings & Fixes Applied

1. **Inverted Post-Evaluation Concordance Index Sign Convention (`slideflow/model/torch_utils.py`)**:
   - `CoxProportionalHazardsLoss` sorts durations descending (`{j: T_j >= T_i}`), training the network's output `log_h` as a genuine Cox log-hazard ratio where **higher values = higher hazard = shorter survival**.
   - However, `slideflow.stats.metrics.concordance_index` documents that Slideflow's `time-y_pred` column must follow the Harrell/lifelines **survival score** convention where **higher values = longer expected survival**. Storing raw `log_h` in `eval_from_model` inverted C-index to `1 - C_index`.
   - **Fix**: Negated `log_h` (`-y_pred[0]`) when constructing `y_pred` in `eval_from_model` (after computing validation `CoxProportionalHazardsLoss` on raw `log_h`), aligning PyTorch survival evaluation with `slideflow.stats.metrics.concordance_index`.
2. **1D `labels` Tensor Concatenation Crash in `SurvivalTrainer._calculate_loss` (`slideflow/model/torch.py`)**:
   - Slideflow's PyTorch TFRecord dataloader yields 1D `(batch_size,)` tensors for single continuous/survival outcomes, causing `torch.cat((labels, event_indicator.unsqueeze(1)), dim=1)` to fail with `RuntimeError: Tensors must have same number of dimensions: got 1 and 2`.
   - **Fix**: Normalized both `labels` and `event_indicator` to 2D `(B, 1)` float32 tensors prior to `torch.cat`.
3. **Zero-Event Mini-Batch Autograd Graph Disconnect (`CoxProportionalHazardsLoss`)**:
   - Returning `torch.tensor(0.0, device=log_h.device)` when `events.sum() == 0` detached the autograd graph and crashed `loss.backward()` on all-censored mini-batches.
   - **Fix**: Returned `log_h.sum() * 0.0` before computing `log_h.max()` and replaced `.view(-1)` with `.reshape(-1)`.
4. **Prospective `Project.predict()`, `sf.model.load()`, and Legacy `'NLL'` Compatibility (`slideflow/model/torch.py`)**:
   - Fixed `KeyError` in `_setup_inputs` when `Project.predict()` passes `config['outcome_labels']` as `labels`, allowed prospective `Project.predict()` on image-only survival models without requiring future `event` annotations, handled `config['model_type'] == 'survival'` in `sf.model.load()`, preserved `Dataset.split` mapping (`survival` → `regression`) from `#466`, and kept `'NLL'` as a backward-compatible alias alongside `'CoxProportionalHazardsLoss'`.
5. **Verification**:
   - Added `test_pr408_torch_cph_tile_survival_trainer` in `scripts/ci/cpu_verification_suite.py` covering loss direction, zero-event autograd backward pass, single-input & multi-input `SurvivalTrainer` training, `sf.model.load`, `Project.evaluate`, and prospective `Project.predict`.

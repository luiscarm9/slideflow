# Audit Report — Upstream PR #422 (`Adding H-optimus-0 and DinoBloom as foundation models`)

- **Upstream URL**: https://github.com/slideflow/slideflow/pull/422
- **Upstream Branch**: `slideflow:foundation_models_change` → `master` (4 commits, 4 files)
- **Original Author**: `ldonle`
- **Fork Audit Branch**: `pr-audit/422-dinobloom`

## Audit Findings & Fixes Applied

1. **Overlap with Slideflow 3.1.0 (`PR #466`)**:
   - `H-optimus-0` (`hoptimus0.py`) and `virchow.py` (`weights_hash` support) were already integrated in `#466`; preserved `#466`'s richer implementations while integrating `DinoBloomFeatures` (`dinobloom.py`).
2. **Accidental Unregistration of `virchow` in `_factory_torch.py`**:
   - Upstream PR `#422` inserted `hoptimus0` and `dinobloom` directly below the existing `@register_torch` decorator of `def virchow`, leaving `def virchow` undecorated and unregistered!
   - **Fix**: Preserved `@register_torch` on all three (`hoptimus0`, `dinobloom`, `virchow`).
3. **Input Resolution Mismatch Crash (`img_size=518` vs `224`) in `DinoBloomFeatures`**:
   - `hf-hub:1aurent/vit_{model_size}_patch14_224.dinobloom` specifies `"input_size": [3, 224, 224]` with `"fixed_input_size": true`, whereas `#422` configured `self.build_transform(img_size=518, ...)`, causing a shape assertion failure on forward pass.
   - **Fix**: Updated `img_size=224` in `DinoBloomFeatures.build_transform`.
4. **Config Serialization Bug (`dump_config`)**:
   - `DinoBloomFeatures.dump_config()` omitted `model_size` (and `weights`), causing `rebuild_extractor()` to silently revert `base`/`large`/`giant` extractors to `small` (384-dim).
   - **Fix**: Persisted `model_size` and `weights` in `dump_config()`, added `model_size` validation, and added offline `pretrained=False` support + `test_pr422_dinobloom_extractor_and_registry`.

## Audit Findings & Hardening Applied

1. **`**kwargs` Forwarding Bug in `save_zarr_compressed`**:
   - Upstream PR `#450` replaced removed internal `zarr.convenience` helpers with `zarr.open_group`, but passed `**kwargs` (the named arrays dict, e.g. `masks=...`, `centroids=...`) into `grp.create_dataset(..., **kwargs)`, causing `TypeError` whenever keyword arrays were stored.
   - **Fix**: Iterated over `kwargs.items()` as dataset names/arrays without forwarding `**kwargs` as dataset creation options.
2. **Full Zarr v3 (`zarr >= 3.0`) `.zip` & `Segmentation.load()` Support**:
   - Zarr v3 removed `zarr.load()` (breaking `Segmentation.load()`) and changed `.zip` handling to explicit `zarr.storage.ZipStore` + `grp.create_array()`.
   - **Fix**: Added `_open_store()` and `load_zarr_arrays()` supporting both Zarr v2 and Zarr v3 `.zip` stores, updated `Segmentation.load()` to use `seg_utils.load_zarr_arrays()`, and guarded top-level `cellpose` imports in `slideflow/cellseg/__init__.py` so mask I/O and outline utilities work even when `cellpose` is not installed.
3. **Added Regression Tests**:
   - Added `test_pr450_zarr_compressed_segmentation_and_outlines` covering positional + keyword Zarr `.zip` round-trips, `Segmentation.save()` / `Segmentation.load()`, and `fast_outlines_list()`.

## Audit Findings & Conflict Resolution

1. **`slideflow/plugin.py` (`pkg_resources` vs defensive plugin loading)**:
   - Upstream `#466` added defensive `try/except` error handling around plugin `load()` and `register()`, but still relied on `pkg_resources.iter_entry_points`, which was removed in modern `setuptools` (`>=81`).
   - **Resolution**: Combined `#466`'s defensive error handling with `importlib.metadata.entry_points(group='slideflow.plugins')`.
2. **NumPy 2.x, PyArrow 20+, & Python 3.12+ Unlock (`setup.py`, `requirements.txt`, `ci.yml`)**:
   - Upstream `#466` replaced removed `np.fromstring` (`np.frombuffer`), `np.in1d` (`np.isin`), and Python 3.13-removed `imghdr` (`filetype`).
   - **Resolution**: Lifted the temporary 3.0.2 `numpy<2.0` and `pyarrow<20` caps and expanded GitHub Actions CI matrix to **Python 3.10, 3.11, and 3.12** running against NumPy 2.x.
3. **Pandas 3.0 MIL Compatibility Preserved (`slideflow/mil/train/_fastai.py`)**:
   - Preserved our `pd.Series(...).value_counts()` fix (upstream `#466` still contained `pd.value_counts(...)`).
4. **Added Regression Tests**:
   - Added `test_pr466_hoptimus0_roi_and_plugins` in `scripts/ci/cpu_verification_suite.py` covering `Hoptimus0Features` registration, `weights_hash`, `ROI.area()`, `ROI.__deepcopy__()`, and `WSI.roi_area()`.
